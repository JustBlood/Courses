## 3) Новый целевой flow (бизнес-логика)

### 3.1 Submit student (practice)

Студент отправляет `questionAnswers: { questionIndex -> [answers...] }`.

#### Для `PRACTICE_TEST`:

- ответы сохраняются;
- для каждого вопроса вычисляется тип балла: `FULL | PARTIAL | ZERO`;
- суммируются баллы по вопросам;
- сравниваются с порогом урока (`passingThresholdPercent`);
- `lessonSubmission.pointsAwarded`:
  - если порог пройден: `lesson.fullPoints`,
  - иначе: `0`.
- после финализации (`completed=true`) студент больше не может менять ответы.

#### Для `PRACTICE_OPEN_ANSWER`:

- ответы сохраняются в question-level progress;
- после submit урок уходит в `PENDING_REVIEW`;
- первичная отправка — ответы по всем вопросам урока;
- повторная отправка после `REWORK` — только по вопросам в `REWORK`.

### 3.2 Review admin

- ревьювер получает урок на проверку с **полным списком вопросов урока** и текущими статусами;
- отправляет решения сразу по всем вопросам урока;
- допустимые вопросные статусы: `ACCEPTED`, `REWORK`, `REJECTED`;
- баллы по вопросу:
  - `ACCEPTED`: `0..fullPoints`;
  - `REWORK`: `0`;
  - `REJECTED`: `0`.

### 3.3 Агрегация финального статуса урока

- если есть хотя бы один вопрос `REWORK` → урок `REWORK`, `completed=false`;
- если `REWORK` нет → урок финализируется (`completed=true`),
  далее по сумме баллов вопросов и порогу урока:
  - пройден: `COMPLETE`,
  - не пройден: `INCOMPLETE`.

После финализации урок не попадает в review и не редактируется студентом.

## 4) Правила scoring (подтверждённые)

### 4.1 SINGLE_CHOICE

- ровно один правильный выбор → `FULL`;
- иначе → `ZERO`.

### 4.2 MULTIPLE_CHOICE

- `FULL`: 100% совпадение выбранных и правильных ответов.
- `PARTIAL`: одновременно:
  - выбрано не более 1 неправильного,
  - и не выбрано не более 1 правильного.
- иначе `ZERO`.

Дополнительный подтверждённый пример-исключение:

- если в вопросе 3 правильных ответа, а студент отметил только 1 правильный,
  это `ZERO` (слишком много пропущенных правильных).

### 4.3 OPEN_ANSWER

- тип балла определяется ревьювером через фактические баллы в диапазоне `0..fullPoints`;
- при `REJECTED` всегда `0`.

## 5) Модель данных (целевая)

### 5.1 Lesson progress (`lesson_submissions`)

Одна актуальная запись на `(student_id, lesson_id)`:

- `lesson_id`
- `student_id`
- `status`
- `completed` (урок финализирован)
- `pointsAwarded` (баллы урока: либо `lesson.fullPoints`, либо `0`)
- `questionProgressJson` (json/jsonb с массивом/мапой прогресса по вопросам)
- мета-поля (`submittedAt`, reviewer fields, comment) по необходимости

### 5.2 Question progress (внутри json/jsonb)

Для каждого `questionIndex` хранить:

- `answer` (массив строк)
- `pointsType` (`FULL|PARTIAL|ZERO`)
- `awardedPoints` (фактические баллы вопроса)
- `reviewStatus` (для open: `PENDING_REVIEW|ACCEPTED|REWORK|REJECTED`, для test может быть null)

## 11) Для точности, сохранён первоначальный запрос пользователя:

В текущем проекте поправить текущую реализацию прохождения уроков по представленным требованиям и моим рассуждениям. Если потребуется - надо по минимуму трогать миграции. Вот мои требования и рассуждения:
Уроки прохождение
Флоу:
Пользователь отправляет ответ на урок в формате: question_id - answer(string)
Бек принимает ответ. Получить урок, Смотрит тип урока - если это тест, то 2.1. Если это открытый ответ, то 2.2
2.1. Получить все вопросы урока; пройтись по всем ответам пользователя и сравнить ответ с правильным. Если множественный вариант ответа - количество неверно отмеченных не более 1 и количество верно отмеченных более 1 - то это частично правильный ответ. Все ответы пользователя сохраняются в БД для дальнейшего просмотра. 
2.2. Сохранить ответы пользователя в БД для дальнейшего просмотра и получения ментором для ревью. Перевести статус урока на PENDING_REVIEW. Важно: урок на PENDING_REVIEW означает, что ревьювер по курсу получит все вопросы урока для проверки. Он может менять свое решение но вопросу в любой момент - даже если вопрос уже засчитан, он может поменять его статус на Требует доработки или Отклонено. Таким образом, не требуется проверять - какие уроки давать ревьюверу для проверки - давать надо вообще все всегда. После того, как ревьювер дал оценку всем вопросам (засчитал/отправил на повторное ревью/отклонил), урок переходит в нужный статус. Если есть хоть 1 вопрос со статусом Переделать - то весь урок в статус REWORK. 

Если все ответы одобрены или отклонены - урок считается завершенным, пользователь более не может менять там ответы, подсчитываются все баллы за все вопросы и проверяется, достаточно ли баллов до проходного значения урока, чтобы засчитались баллы за урок. Если проходное количество баллов набрано - урок считается завершенным и за него даются баллы курса.



Сущности:
Прогресс пользователя по уроку:
lesson_id
answers (List) 
completed - признак, что урок пройден, т.е. пользователь уже не может менять ответы на вопросы по нему
points - количество баллов за урок. Если порог прохождения пройдет - то fullPoints из урока, иначе - 0

Прогресс пользователя по вопросу:
question_id
answer
points (не цифра, а ТИП - полный балл/частичный балл/0) 

Прогресс пользователя по вопросу содержится в 1 jsonb-колонке сущности прогресса по уроку. 

Подсчет баллов за вопрос:
Тестовый 1 вариант ответа: полный балл за правильно выбранный, 0 в остальном случае
Тестовый несколько вариантов ответа: полный балл за выбор только всех верных. Частичный балл, если выбрано <= 1 неверного варианта ответа и <= 1 верного не выбрано. 0 в остальном случае
Открытый ответ - балл определяется ревьювером в диапазоне от 0 до fullPoints
