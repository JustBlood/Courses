# PRD-06: Критерии приемки

## 1. Назначение раздела
Фиксация тестируемых критериев «готово» для функциональных требований FR-001..FR-019 и FR-101..FR-114.

Правило приёмки:
1. Каждый FR имеет минимум один проверяемый acceptance-критерий.
2. Проверка проводится по модели Given/When/Then.
3. Для сложных сценариев допускается несколько критериев на один FR.

---

## 2. Критерии приемки для MVP (FR-001..FR-019)

| AC-ID | FR-ID | Критерий приемки (Given / When / Then) |
|---|---|---|
| AC-001 | FR-001 | Given администратор авторизован, When создаёт пользователя с обязательными полями и (опционально) назначает группы/курсы, Then пользователь создан, связи назначений сохранены. |
| AC-002 | FR-002 | Given пользователь создан, When система отправляет уникальную ссылку и пользователь задаёт пароль, Then аккаунт активирован и может войти в систему. |
| AC-003 | FR-003 | Given существующий пользователь, When администратор редактирует его данные и пользователь редактирует свой профиль в разрешённых пределах, Then изменения сохраняются согласно правам доступа. |
| AC-004 | FR-004 | Given пользователь в системе, When администратор меняет роль, Then доступные функции и ограничения меняются без дополнительной активации аккаунта. |
| AC-005 | FR-005 | Given администратор в модуле курсов, When создаёт/редактирует курс с обязательными полями и параметрами прохождения, Then курс сохраняется и доступен в каталоге. |
| AC-006 | FR-006 | Given курс создан, When администратор добавляет урок, Then система позволяет выбрать только тип `THEORY` или `PRACTICE` и корректно сохраняет структуру курса. |
| AC-007 | FR-007 | Given теоретический урок, When администратор выбирает формат контента (текст/YouTube/PDF), Then урок отображается и открывается студенту в выбранном формате. |
| AC-008 | FR-008 | Given практический урок, When администратор добавляет вопросы поддерживаемых типов, Then все типы вопросов корректно сохраняются и доступны в режиме прохождения. |
| AC-009 | FR-009 | Given настройки баллов, When администратор задаёт дефолтные и индивидуальные баллы (включая частичную оценку), Then система применяет их при расчёте результата. |
| AC-010 | FR-010 | Given курс и пользователи, When администратор переводит пользователей между списками «зачислены/не зачислены», Then доступ к курсу обновляется в соответствии с новым состоянием. |
| AC-011 | FR-011 | Given курс и пользователи-администраторы, When назначены проверяющие, Then у назначенных появляется рабочая область проверки с ожидающими ответами. |
| AC-012 | FR-012 | Given студент зачислен на курс, When открывает и завершает теоретический урок, Then фиксируется прохождение и начисляются баллы по правилам урока. |
| AC-013 | FR-013 | Given студент отправляет тестовые ответы, When система выполняет автопроверку, Then выставляется результат, статус попытки и начисляются баллы. |
| AC-014 | FR-014 | Given студент отправляет развёрнутый ответ, When назначенный проверяющий проверяет ответ (в т.ч. может вернуть на доработку), Then статус и начисленные баллы корректно обновляются. |
| AC-015 | FR-015 | Given студент/администратор открывает личную статистику, When выбирается конкретный пользователь, Then отображаются курс, баллы, эффективность и % выполнения по согласованным формулам. |
| AC-016 | FR-016 | Given администратор открывает статистику курса, When загружается список студентов, Then отображаются ФИО, баллы, эффективность и % выполнения для каждого. |
| AC-017 | FR-017 | Given администратор формирует сводные отчёты, When выбирается отчёт по курсу или общий, Then структура колонок соответствует PRD и данные выводятся корректно (включая поля, которые по ТЗ пустые). |
| AC-018 | FR-018 | Given авторизованный пользователь, When вводит текущий и новый пароль, Then пароль успешно меняется и старый перестаёт работать. |
| AC-019 | FR-019 | Given пользователь инициировал восстановление пароля, When проходит шаги подтверждения и задаёт новый пароль, Then доступ восстанавливается с новым паролем. |

## 3. Критерии приемки для post-MVP (FR-101..FR-114)

| AC-ID | FR-ID | Критерий приемки (Given / When / Then) |
|---|---|---|
| AC-101 | FR-101 | Given администратор в модуле разделов, When создаёт/редактирует раздел с названием, описанием и приоритетом, Then раздел сохраняется и участвует в навигации каталога. |
| AC-102 | FR-102 | Given страница раздела, When администратор создаёт курс из этого раздела, Then курс автоматически привязывается к выбранному разделу. |
| AC-103 | FR-103 | Given администратор в модуле программ, When создаёт программу из упорядоченного списка курсов, Then программа сохраняет порядок курсов. |
| AC-104 | FR-104 | Given программа обучения, When администратор задаёт дедлайн и условие доступа к следующему курсу, Then система применяет выбранное правило прохождения. |
| AC-105 | FR-105 | Given программа создана, When администратор назначает её пользователю или группе, Then назначение отражается у всех целевых пользователей. |
| AC-106 | FR-106 | Given администратор в модуле групп, When создаёт/редактирует группу с типом (общая/компания/подразделение/должность), Then группа доступна для дальнейших назначений. |
| AC-107 | FR-107 | Given пользователь и набор групп, When администратор изменяет членство пользователя в группах, Then изменения сохраняются и видны в профиле/группах. |
| AC-108 | FR-108 | Given группа пользователей, When администратор назначает группе курс/программу, Then все участники группы получают соответствующий доступ. |
| AC-109 | FR-109 | Given страницы каталогов (курсы/пользователи/группы), When пользователь выполняет поиск/фильтрацию, Then отображаются релевантные результаты в рамках прав доступа. |
| AC-110 | FR-110 | Given практический урок, When задан порог прохождения, Then урок считается пройденным только при достижении порога. |
| AC-111 | FR-111 | Given практический урок с лимитом попыток, When студент достигает лимита, Then следующая попытка недоступна по правилам урока. |
| AC-112 | FR-112 | Given курс/урок с ограничением времени, When время истекает, Then применяется правило завершения/непрохождения согласно настройкам. |
| AC-113 | FR-113 | Given урок с включённой рандомизацией и/или ограниченной выборкой вопросов, When студент начинает попытку, Then вопросы выдаются согласно заданным параметрам. |
| AC-114 | FR-114 | Given урок с включённым `stopLesson`, When студент не прошёл текущий урок, Then переход к следующему уроку блокируется даже при свободном порядке уроков курса. |

## 4. Сквозные критерии качества приемки

1. Все критерии MVP покрыты интеграционными/сквозными тестами критических сценариев.
2. Для post-MVP покрыты тесты ключевых расширений (группы, программы, ограничения практики).
3. Функции аутентификации, смены/восстановления пароля и контроль ролей проверены отдельным набором security-тестов.
4. Отчёты проверены на корректность формул и формата колонок.

---

## 5. Exit Criteria релизов

### 5.1. Готовность MVP к демонстрации
1. Выполнены AC-001..AC-019.
2. Критичные дефекты уровня Blocker/Critical отсутствуют.
3. Минимальные NFR для MVP из PRD-03 подтверждены.

### 5.2. Готовность post-MVP к приемке
1. Выполнены AC-101..AC-114.
2. Не нарушены ранее принятые критерии MVP.
3. Целевые post-MVP NFR подтверждены на стенде/контуре приёмки.
