# Task Flow and Modes

## Что такое задача
Задача — это атомарное изменение или доработка разрабатываемой системы. Ограничена по цели, критериям, изменениям.

## Целевой флоу выполнения задач
1. Прочитать обязательные документы из `10-memory-bank-workflow.md`.
2. Если требуется - выбрать субагента для анализа необходимых пунктов PRD и задачи из переданного пользователем тикета.
3. Зафиксировать рамки задачи, критерии готовности и риски. Если используется субагент - передать эту задачу ему.
4. Сформировать план работ. Если используется субагент - получить его анализ и на его основании сформировать план работ.
5. Выполнить реализацию/изменения после утверждения плана пользователем.
6. Обновить `memory-bank/05-task-execution-progress.md` (если задача содержит > 300.000 токенов контекста) и `02-active-context.md`.
7. После ПОЛНОГО завершения — обновить `06-system-development-progress.md`.

## Работа по режимам
- **PLAN MODE**: анализ, декомпозиция, уточнение границ, без изменений кода.
- **ACT MODE**: внесение изменений, валидация, фиксация прогресса.

## Анализ задачи
1. Прочитать обязательный контекст memory-bank.
2. Определить релевантные PRD-главы.
3. Сформировать план реализации.
4. При широком ресерче использовать субагентов.
5. Зафиксировать выводы в `02-active-context.md`.

## Обязательные элементы, которые требуется продумать перед реализацией
- Цель и ожидаемый результат.
- Границы (что входит / не входит).
- Источник требований (PRD/комментарии).
- Критерии готовности и проверки.
- Риски и зависимости.

## Правило для длинных задач
- Если контекст растёт и есть риск упора в лимит:
  1. Обновить `05-task-execution-progress.md`.
  2. Обновить `02-active-context.md`.
  3. Продолжить через `/newtask` с загрузкой этих документов.
