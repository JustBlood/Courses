# Task Flow and Modes

## Приоритет правил
- Для всех правил по token budget, checkpoint и обновлению memory-bank приоритет имеет `.clinerules/10-memory-bank-workflow.md`.
- При расхождении между этим файлом и `.clinerules/10-memory-bank-workflow.md` — следовать `.clinerules/10-memory-bank-workflow.md`.

## Что такое задача
Задача — это атомарное изменение или доработка разрабатываемой системы. Ограничена по цели, критериям, изменениям.

## Целевой флоу выполнения задач
1. Прочитать обязательные документы из `10-memory-bank-workflow.md`.
2. Выбрать задачу из `memory-bank/tasks.json` по правилам, описанным в нём. 
3. Выполнять задачу по гайдалайну из секции agent_instructions файла `memory-bank/tasks.json`.
4. Перед началом реализации задачи, выполнить анализ и проектирование решения с помощью субагентов, в случаях, описанных в `.clinerules/50-subagents-guidelines.md`
5. Зафиксировать рамки задачи, критерии готовности и риски. Если используется субагент - передать эту задачу ему.
6. Сформировать план работ. Если используется субагент - получить его анализ и на его основании сформировать план работ. Полный подробный контекст и план зафиксировать в файл `.clinerules/02-active-context.md`
7. Выполнить реализацию/изменения после утверждения плана пользователем.
8. Если срабатывает правило Token Budget Gate - следовать инструкциям для этого случая в `.clinerules/02-active-context.md`
9. По ПОЛНОМУ завершению задачи ты должен весь активный контекст из файла `memory-bank/02-active-context.md` копировать в файл-артефакт по выполнненной задаче в директорию `memory-bank/task-artifacts` и обязательно добавить ссылку на артефакт в файл `memory-bank/05-task-execution-progress.md`. Если задача содержала архитектурно важные изменения - обновлять `memory-bank/06-system-development-progress.md`.
10. Чтобы посмотреть полную информацию по задаче, ты можешь использовать подготовленные python-скрипты: `memory-bank/find_task.py` (пример вызова: `python find_task.py TASK-001`) и `memory-bank/change_task_status.py` (пример вызова: `python change_task_status.py TASK-001 done`, варианты статусов = pending, done, obsolete). Используй эти скрипты приоритетно, вместо полного чтения файла `memory-bank/tasks.json`

## Анализ задачи
1. Прочитать обязательный контекст memory-bank.
2. Определить релевантные PRD-главы.
3. Сформировать план реализации.
4. Использовать субагентов по правилам из `.clinerules/50-subagents-guidelines.md`.
5. Зафиксировать выводы в `02-active-context.md`.

## Обязательные элементы, которые требуется продумать перед реализацией
- Цель и ожидаемый результат.
- Границы (что входит / не входит).
- Источник требований (PRD/комментарии).
- Критерии готовности и проверки.
- Риски и зависимости.

## Правило для длинных задач
- Для длинных задач и превышения лимита контекста применять обязательный `Token Budget Gate` из `.clinerules/10-memory-bank-workflow.md`.
